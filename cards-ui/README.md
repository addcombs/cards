# cards

Standalone Angular 21 and Angular Material 21 frontend with responsive navigation,
adjustable brightness, Cognito sign-in and registration, account profile flows,
and a sports card dashboard. The signed-in toolbar uses the theme surface color with primary-colored text and icons,
over a decorative inline SVG pixel mosaic (`src/app/theme/toolbar-background.ts`)
filled with the theme's primary and secondary colors, so it follows light/dark mode and brightness. The footer
displays the account API's health, polling `/actuator/health` every 5 minutes.
The dashboard has Baseball, Basketball, Football, and Hockey tabs, also reachable from the side
menu, each showing that sport's cards from `/api/cards` in two expandable panels: those with an eBay
listing URL under Current eBay Listings, then the rest under Sold, both open at first,
each split into a panel per PSA grade, highest first. The cards fly in one after another as a panel
opens, and sold cards are stamped SOLD.
A card shows the front of its PSA slab above a copy of the slab's label: year and set, any variety
and the player on the left, card number, grade and PSA cert number on the right. Clicking the photo turns it to the back and again to the front. Hovering over it (or focusing it, and always
on touch screens) shows a small zoom button in its corner, which opens it in a dialog (`src/app/main/cards/card-zoom.ts`) to zoom up to 400% with
the buttons, mouse wheel or pinch and pan by dragging, from the larger `-zoom.jpg` photos. A card with
an eBay listing URL links to it. Members of the Cognito group `admins` also see a pencil button in the bottom left of
each card's details, which opens a dialog to edit them (`src/app/main/cards/card-edit.ts`); the API
checks the group too. The photos load from `photosUrl` in `src/app/project.settings.ts`:
the UI's own host at `/images/photos/`, which CloudFront serves from the photo bucket.
The Material 3 palettes are generated from primary crimson `#DC143C` and secondary Material red accent A200 `#FF5252`
(`src/app/theme/generated_theme-colors.scss`, via `ng generate @angular/material:theme-color`).

## Local setup

Requirements: Node.js and npm.

```bash
npm ci
npm start
```

Open `http://localhost:4200/`. The local `/api/account`, `/actuator/health`,
`/swagger-ui`, and `/v3/api-docs` proxies target `http://localhost:8080` in `proxy.conf.json`
(`src/app/api-url.ts` keeps API paths relative in development and prefixes the API host in production).
The toolbar's ⋮ menu links to the backend's Swagger UI and opens an About dialog.
A compatible backend must be
running on port 8080; changing the proxy port is not a substitute for starting it.
No backend is bundled or provisioned.

## Brightness

The toolbar shows a sun for the light profile or a moon for the dark profile.
Click the brightness icon in the signed-in toolbar to show or hide the horizontal
slider to its left, with an accessible label and no visible text. Opening it
does not change the theme. Slide right for
light surfaces (100%) and left for dark surfaces (0%).
Backgrounds move through neutral grays from `#121212` (dark) to `#FAFAFA` (light),
without a primary-color tint. Surface text uses black or white, whichever provides greater
contrast. Primary buttons, icons, borders, and highlights steadily darken from
tone 80 on the darkest background to tone 40 on the lightest background.
Primary accents can have reduced contrast against backgrounds near the middle
of the slider. Filled primary
controls use contrasting black or white text.
The level is saved locally and restored on reload; without a saved level it starts
from the system's light or dark preference.
Keyboard users can adjust the slider with arrow keys, Home, and End.

## Authentication and account configuration

`src/app/project.settings.ts` is generated by the setup scripts (`Sync-UiConfig` in
`..\scripts\common.ps1`) from `..\project.json` and `..\state\cognito-pool.json`; edit those,
not the generated file. It holds the app's public Cognito user-pool ID, app-client ID,
sign-in domain, the sign-in/sign-out redirects for `http://localhost:4200/` and the app's
domain, and the API's URL. Sign-in uses authorization-code OAuth with PKCE and a public
client without a client secret.

To run the full stack locally, run `..\scripts\start-all.ps1` in PowerShell: it installs
dependencies, builds and tests both apps, then starts the API on port 8080 and this
UI on port 4200 (logs in `..\logs`).

Until `..\scripts\create-cognito-pool.ps1` has run, the app displays an authentication setup notice. Build and
unit test success do not verify live authentication or account integration;
verify those flows in a browser after configuring the services.

The backend must validate Cognito ID tokens and support authenticated
`GET /api/account` and `PUT /api/account` requests with an
`Authorization: Bearer <ID token>` header. Account details contain `email`,
`firstName`, `lastName`, and `phoneNumber`. Updates contain required `firstName`
and `lastName` and nullable `phoneNumber`; email comes from the verified token.
The backend returns 404 for a missing account, 401 for invalid authentication,
and 409 for conflicting account identity.

The health endpoint must be publicly readable to the app without an access
token. The development proxy does not apply to production builds: they call the API at
its own host (`apiUrl` in `project.settings.ts`, e.g. `https://api.cards.acombs-dev.com`),
which must allow this app's origin through CORS. Keep credentials on the backend, never in the browser app, and do not expose
unauthenticated legacy backend endpoints to untrusted clients.

## Build and tests

```bash
npm run build
npm test
```

Build output is written to `dist/`. Unit tests use the Angular CLI and Vitest.
The initial bundle (about 830 kB, 180 kB compressed, mostly Angular Material and Amplify Auth)
warns above 1 MB and fails above 1.5 MB. Each component stylesheet warns above 4 kB, so the
toolbar's brightness-slider styles live in `src/app/main/brightness-control.scss`, apart from `app.scss`.
